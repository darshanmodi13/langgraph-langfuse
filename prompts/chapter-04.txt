CHAPTER 4: "Parallel work and quality loops"

WHAT EXISTS SO FAR: step3_tools.py: a traced agent loop with search_document and create_bug_ticket tools.

THIS CHAPTER:
- The problem: a ticket with several questions answered one by one is slow.
- Send: returned from the function given to add_conditional_edges; each Send("node", input) starts one run of that node with its own input. "Conditional" here means "an edge that runs a function". Each worker gets only its own input (a WorkerState).
- Super-steps: rounds; same-round nodes run in parallel; the next round waits for all of them (like await Promise.all). That is how the synthesizer runs once, after the slowest worker, without knowing how many workers exist.
- Reducers for parallel writes: Annotated[list[str], operator.add], and the error without one.
- max_concurrency in the config; it limits one invoke() only; Ollama also queues requests beyond its own limit.
- Evaluator-optimizer with with_structured_output: route FAIL back to the node that creates content, make it use state.get("feedback"), add an attempts counter with MAX_ATTEMPTS, and the operator.add append caveat.
- Use the parallel-work facts in section 6 of 00-book-rules.md.
- In Langfuse: overlapping worker timings, and the synthesizer starting after the slowest one.
