CHAPTER 3: "Tools and the agent loop"

WHAT EXISTS SO FAR: step2_routing.py: a traced graph that classifies a ticket and routes it with Command.

THIS CHAPTER:
- What a tool is: a normal function the LLM can ASK to run; your code runs it (like a frontend calling fetch).
- @tool: name from the function name, description from the docstring, arguments from type hints; the only things the LLM reads. State the tool facts in section 6 of 00-book-rules.md.
- llm.bind_tools(tools) and why it adds input tokens.
- AIMessage.tool_calls (name, args, id); ToolNode runs the function and appends a ToolMessage whose tool_call_id matches.
- step3_tools.py loop: START -> llm_call -> should_continue -> tool_node -> back to llm_call (a fixed add_edge("tool_node", "llm_call")) -> ... -> END. should_continue reads the last message with getattr(last_message, "tool_calls", None) (like optional chaining) and returns "tool_node" or END.
- How messages grow: Human -> AI(tool_calls) -> Tool -> AI(final answer). The system prompt is added inside the node and not stored in state.
- In Langfuse: two GENERATIONs per request (before and after the tool), the tool call in the first generation's output, the ToolMessage, and load_duration for cold starts.
